## 1. 背景与目标

现有 Tempokiri 是纯 CLI 的节奏感知音频剪辑工具（Python + librosa）。本项目将其升级为
**Tempokiri 工作站**：一个单 HTML 文件交付的浏览器端工具，支持音频/视频拖入、波形与节拍网格
可视化、按小节选段、试听、多段拼接、导出 WAV/MP3。

定位：小圈子分享（双击即用、单文件可分发），面向 MV/音乐 Remix 剪辑场景。

## 2. 功能范围（首版）

### 核心（必做）
1. 拖入音频（mp3/wav/ogg/m4a/flac）或视频（mp4/webm）
2. 视频文件显示预览窗，波形基于其音轨（后台静音快速播放采集 PCM，带进度提示）
3. **确认制节拍设置**：BPM、拍号、偏移在小窗口中输入，自动识别仅填充不应用，
   必须点击确认才绘制网格
4. 节拍设置持久化（localStorage，文件指纹 = 文件名+大小+修改时间），再次拖入自动应用
5. 波形 + 节拍网格渲染，小节线可视化
6. 按小节点击选段 / 拖拽范围选择
7. 选中段落循环试听
8. 多段拼接顺序调整（上移/下移/删除）
9. 每段淡入淡出设置
10. 交叉淡化拼接导出 WAV

### 可选已定（进入首版）
- MP3 导出（内嵌 lamejs）
- 手动微调：BPM/偏移在小窗口中修改，重新确认即重新绘制网格

### 明确不做（首版）
- 变速不变调（soundtouch）
- 多轨叠加
- 云端/后端

## 3. 架构

### 交付形态
- 开发期：多文件 JS 模块 + `index.html`，Node 可跑单元测试
- 发布期：`build.py` 拼接成 `dist/remix-workstation.html` 单文件（JS 内嵌，零外部请求）

### 目录结构
```
remix/
├── src/
│   ├── main.js          # 入口：模块装配、全局状态、事件绑定
│   ├── audio.js         # 解码（decodeAudioData）、视频 PCM 采集（captureStream+ScriptProcessor）
│   ├── analysis.js      # 核心算法：STFT、onset 检测、BPM 估计、相位估计、网格生成
│   ├── render.js        # Canvas 波形、网格覆盖层、选区高亮
│   ├── interact.js      # 点击/拖拽选段、波形缩放
│   ├── sequence.js      # 段落序列管理
│   ├── modal.js         # 节拍设置小窗口（确认制）
│   ├── store.js         # localStorage 节拍设置缓存
│   ├── export.js        # 离线渲染 + WAV 编码 + MP3（lamejs）
│   └── ui.js            # DOM 模板、工具栏、段落列表
├── lib/lamejs/          # 唯一第三方依赖（MP3 编码）
├── index.html           # 开发入口
├── build.py             # 打包脚本 → dist 单文件
├── tests/               # Node 单测（analysis、export 纯函数）
└── dist/remix-workstation.html
```

### 数据流
```
拖入文件 → audio.js 解码/PCM 采集 → 状态就绪
  → modal.js 确认节拍设置 → analysis.js 生成网格
  → render.js 画波形+网格 → interact.js 选段
  → sequence.js 维护序列 → export.js 离线渲染导出
```

### 关键原则
- **纯函数与 DOM 解耦**：analysis.js、export.js 的算法/编码函数不碰 DOM，
  可在 Node 下直接测试（CommonJS/ESM 双兼容写法或条件导出）
- **单一状态对象**：`state = { audioBuffer, pcm, sampleRate, bpm, timeSignature,
  offset, bars, selections, sequence }`；渲染只读 state，交互只改 state 后触发重绘
- **视频 PCM 采集**：`video.captureStream()` + `MediaStreamAudioSourceNode` +
  `ScriptProcessorNode` 静音快速播放采集 Float32 PCM（避开 AudioWorklet 的
  Blob URL 加载问题，兼容 file:// 场景）；采集进度显示在预览窗

## 4. 算法设计（基础检测 + 手动微调）

1. **预处理**：PCM 降采样到 22050 Hz（分析用），mono
2. **STFT**：自实现 radix-2 FFT，帧长 2048、hop 512、Hann 窗
3. **Onset 检测**：频谱通量（spectral flux）→ 半波整流 → 平滑 → 局部峰值
4. **BPM 估计**：onset 包络自相关，60–200 BPM 范围内取最大峰
5. **相位（偏移）估计**：候选偏移对 onset 吻合度投票，选最优
6. **网格生成**：`拍长 = 60/BPM`，`小节长 = 拍长 × 拍数`，
   `网格线 = 偏移 + n × 小节长`，小节从 1 编号
7. 用户可手动改 BPM/偏移/拍号，重新确认即重绘

## 5. UI 与交互逻辑

### 布局（深色 DJ 风格）
```
┌──────────────────────────────────────────────┐
│ 工具栏：导入 | 设置节拍 | 导出(WAV/MP3)        │
├──────────────────────────────────────────────┤
│ 主区：波形画布（网格线、选区高亮，可缩放）      │
│       [视频预览窗：若为视频文件]                │
├──────────────────────────────────────────────┤
│ 段落序列：卡片列表（序号/范围/时长/淡入淡出/操作）│
└──────────────────────────────────────────────┘
```

### 关键交互流程
1. **拖入文件** → 波形就绪，网格未绘制，主区显示引导提示「点击「设置节拍」配置网格」
2. **设置节拍小窗口**（确认制）：
   - 字段：BPM（数字）、拍号（分子 1-16 / 分母 1,2,4,8,16）、偏移（秒，可负）
   - 「自动识别」按钮：运行分析，**填充**输入框（视频需先采集，显示进度）
   - 「确认」：应用并绘制网格、关闭、写缓存；「取消」：放弃
3. **再次拖入同一文件** → 自动应用缓存设置并绘制网格，提示「已应用上次设置」
4. **选段**：点击小节添加该小节；拖拽覆盖多个小节
5. **试听**：选中段落循环播放（视频则预览窗同步播放）
6. **导出**：离线渲染拼接 → 下载 WAV（默认）/ MP3

## 6. 错误处理
- 不支持的文件格式 → 明确提示
- 视频 PCM 采集失败（浏览器不支持 captureStream）→ 提示改用音频文件
- BPM 检测失败（无清晰节拍，如纯人声/环境声）→ 自动识别留空并提示手动输入
- 大文件（>100MB 音频 PCM）→ 提示内存压力
- 导出渲染失败 → 保留原因提示

## 7. 测试策略
- Node 单测（无 DOM 依赖的部分）：
  - FFT 正确性（已知信号）
  - onset/BPM 检测：合成节拍信号（已知 BPM）验证误差范围
  - 网格生成：给定 BPM/拍号/偏移 → 期望小节边界
  - WAV 编码：往返解码一致性
- 浏览器手动验证：拖入音频/视频、设置节拍、选段、试听、导出

## 8. 验收标准
1. 单 HTML 文件双击打开即用，无外部请求
2. 音频/视频拖入、波形渲染正常
3. 确认制节拍设置：自动识别仅填充、确认才应用；缓存复用生效
4. 选段、试听、排序、淡入淡出、导出 WAV/MP3 全链路可用
5. Node 单测全绿

## 9. v2 迭代变更（2026-08-11 确认）

### 9.1 分段网格（变速歌曲支持）
- 网格模型从单 BPM 改为**分段网格**：每段 `{bpm, beatsPerBar, beatUnit, 小节数|时长}`，
  第 1 段起点 = 全局偏移，第 N 段起点 = 前段起点 + 前段长度；小节号跨段连续编号
- **自动识别规则**：仅一段 → 整曲识别；多段时第 N 段识别需前 N-1 段长度已确定；
  该段未指定长度 → 识别窗口 [段起点, 末尾]；指定长度 → 仅识别该窗口；
  识别出的偏移为段内相位
- 渲染：段边界明显线 + 段标签；网格线按各段 BPM/拍号绘制
- 设置窗口支持**网格细分**（每拍 1/2/4 条线）与**偏移 3 位小数**

### 9.2 交互重排
- 左键拖拽 = 选定区间（高亮，不落列）；「添加选中区间」按钮入列；再次拖拽替换
- 单击波形 = 设置播放起点并从该处播放原曲（播放线跟随）
- 双击 = 选定该小节；「▶ 预览剪辑结果」= 按序列顺序播放

### 9.3 视频
- 预览窗改为左上角浮层；**导入时即自动采集音轨**（静音 4 倍速播放，进度条），
  失败降级为手动 BPM

### 9.4 导出
- 合并为单个「导出」按钮 + 参数弹窗：格式（WAV/MP3）、MP3 码率、交叉淡化时长、文件名
- **视频合成（WebCodecs）**：demux（mp4box.global.js）→ VideoDecoder 解码 →
  按选区时间窗筛选帧并重建时间戳 → VideoEncoder 重编码 → 与合成音频 mux → MP4 输出；
  流式管线避免帧驻留；不支持 WebCodecs 时视频选项灰掉；WebM 导出延后

### 9.5 依赖
- `lib/mp4box.global.js`（MP4Box.js 1.4.7，ESM 尾部 export 转 window.mp4box）

## v3 变更（2026-08-11）

### 1. 导入交互简化
- 删除工具栏「导入文件」按钮；未导入文件时波形区提示「拖入音频或视频文件，或点击此处选择文件开始剪辑」。
- 单击空白波形区（未导入状态）直接打开文件选择窗口；仅支持单曲/单个视频剪辑。

### 2. 末段「剩余所有」逻辑
- 节拍设置面板最后一段的长度方式与数量列固定显示「剩余所有」，无需填写。
- 校验跳过末段长度；确认后末段自动延伸至曲目末尾（resolveSegments 既有行为）。
- 删除全局「网格细分」下拉，改为每段独立的「网格分辨率」（每小节线数）输入列。

### 3. 网格分辨率精确到段落
- 段定义新增 `resolution`（每小节网格线数），buildGrid 按段应用（默认 = 拍号分子，即每拍一条线）。
- 自动识别成功后若未手动设置分辨率，默认填入该段拍号分子（4/4、4/3 → 4；8/6 → 8）。

### 4. 设置窗口宽度
- 修复设置窗口内容超出默认宽度的问题：modal-wide 显式 720px（max-width: calc(100vw - 40px)），表格列宽收紧。

### 5. BPM 检测器重写（自相关主导周期）+ 首 onset 偏移
- 原 gridCost 最近网格线距离对八分/十六分混合节奏失效（真曲 143 BPM 检出 197）。
- 改为：滞后域自相关（0.3–1.0s 对应 60–200 BPM，±0.03s 配对窗口）→ 主峰 ±0.04s 加权中心 → 60/lag 取整。
- 半拍/八分假峰（0.209s）天然落在扫描范围外；倍速滞后配对 onset 数少而落选。
- BPM 输出支持 0.1 精度：自相关主周期后局部细化（±3 BPM、0.1 步长、onset 最近拍线距离最小）。
- offset 语义 = 首条网格线（拍线）的绝对位置 = 第一个 onset（开头第一个可听见的瞬态）：用户按听感校准（心予報 mp3 手动 143/0.46 ≈ 首个 onset 0.464s）时无需相位换算；首个 onset 为弱装饰音时可在设置窗口手动微调。
- 修复：自动识别结果的 offset 未填入偏移输入框（状态栏文本有、输入框恒 0）——识别第 1 段后写入 mOffset。
- 实测：`心予報` MP3（剪辑版）自动识别 BPM 143、offset 0.464s，与用户听感校准 143/0.46 差 0.004s ✓；MP4（完整 MV，intro 13s）BPM 143、offset 13.235s（首线对齐首个 onset）。
- 负 offset（如 -0.09）链路正常：buildGrid 从负值起画、0s 前线段自动裁剪，首条可见线 = offset + 拍；视觉上差异小于半拍时在全曲缩放下不明显（非 bug，可放大波形核对或手动微调）。

### 6. 顶部快捷调整与播放交互重排（2026-08-11 二轮）

- 工具栏中部新增 BPM/offset 快捷栏（无输入框，各 6 个按钮 ±1/±0.1/±0.01）：
  - BPM 显示标注段落号（`BPM（第 N 段）`），修改的是播放起点所在段，立即重建网格并重绘；
  - offset 针对全曲，修改立即生效并重绘；
  - 无打开文件或未设置网格时整栏隐藏。
- 左键单击波形改为**仅移动播放起点**（若在播放则暂停），并把顶部 BPM 切换到该段；波形上以青色虚线画出播放起点标记；播放原曲改为显式按钮。
- 播放按钮重排：`▶ 从此处开始播放`（原曲，从播放起点）与 `⏸ 暂停` 放在波形图旁；`▶ 播放拼接序列` 放在拼接序列列表旁；`停止` 保留在工具栏。

### 9. 序列卡片让位拖拽 + 提示修复（2026-08-11 五轮）

- 拖拽排序升级为**实时让位**：拖动中被拖卡与目标位之间的卡片以 120ms 过渡平移让位，松手后落位重排；被拖卡半透明跟随。
- 修复「正在解码音频」提示不消失：`#waveHint` 的 `display: flex` 覆盖了 `hidden` 属性的 `display: none`，补 `#waveHint[hidden] { display: none; }`。
- 「＋ 添加选中区间」按钮从工具栏移至控制条（⏹ 停止之后），工具栏仅剩 设置节拍/导出。

### 10. 选区部分覆盖即选（2026-08-11 六轮）

- `snapRange` 从「最近边界吸附」改为「区间交集」：只要拖拽范围与某小节有任何重叠（哪怕只覆盖一点），该小节即被选中。
- 边界语义：左闭右开（b.startTime < t1 && b.endTime > t0）；t0≈t1 落在边界上时取包含 t0 的小节（双击选小节行为不变）。
- 实测：拖拽 1.9s–2.1s 跨 2s 边界 → 第 1–2 小节。

### 11. 滚轮行为调整 + 视图 clamp 修复（2026-08-11 七轮）

- 纯滚轮 = 水平平移（向下滚时间前进、向上滚后退）；Ctrl+滚轮 = 以指针位置为中心缩放（原为无修饰滚轮缩放）。
- 修复 `setView` clamp bug：`Math.min(0, d-span)` 使视图窄于音频时 start 恒为 0、无法平移/居中；改为 start ∈ [min(0, d-span), max(0, d-span)]。
- 提示文案更新：单击定位 · 双击选小节 · 拖拽选区 · 滚轮平移 · Ctrl+滚轮缩放。
